# Работа с проектом

- Запускайте команды из корня. Восстановление: `dotnet restore Calendar.slnx --configfile NuGet.Config`, `npm --prefix api-contract ci`, `npm --prefix frontend ci`. Используйте только публичный nuget.org через репозиторный `NuGet.Config`.
- Локальный запуск: `dotnet run --project src/Calendar.Api --launch-profile http` (порт 5005), в другом терминале `npm --prefix frontend run dev`. Vite проксирует `/api` только в dev. Dockerfile собирает API и SPA в один образ; контейнер сам слушает `PORT` (по умолчанию 8080).
- Контракт редактируется в `api-contract/main.tsp`. После изменения запустите `npm --prefix api-contract run generate:all` (Node.js 22, Java 21): TypeSpec → OpenAPI → серверные C#-артефакты и frontend SDK. Генерируемые файлы редактируйте только генератором.
- Проверки CI: `dotnet format Calendar.slnx --verify-no-changes --no-restore`, `dotnet build Calendar.slnx -c Release -warnaserror --no-restore`, `dotnet test Calendar.slnx -c Release --no-build --no-restore`, `npm --prefix frontend run lint`, `npm --prefix frontend test`, `npm --prefix frontend run build`. Сначала restore; тесты с `--no-build` — только после Release-сборки. Backend-тесты используют `WebApplicationFactory<Program>`, не запускайте для них отдельный сервер.
- Сохраняйте `.github/workflows/hexlet-check.yml` и название репозитория. Коммиты агентов и squash-сообщения оформляйте по Conventional Commits (`feat:`, `fix:`, `test:`, `ci:`, `docs:`, `chore:`) со ссылкой на тикет. Release-please создаёт release-PR после push в `main`; перед merge release-PR проверьте его точный head отдельно, если CI не стартовал автоматически.
- Issues/спецификации: `docs/agents/issue-tracker.md`. Словарь: `GLOSSARY.md`; значимые решения: `docs/adr/`. MCP: `opencode.json` и раздел README про настройку агентной разработки.
